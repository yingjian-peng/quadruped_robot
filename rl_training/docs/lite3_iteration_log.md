## v3 固定协议基线

对 `2026-10-05_23-26-13_lite3_flat_posture_v3/model_4999.pt` 使用 seed 42、5 trials × 11 种固定命令，每回合 8 s、前 2 s warmup。关闭域随机化与观测噪声。结果在同一 run 的 `benchmark/rollouts.csv` 和 `benchmark/summary.csv`。跌倒判据为机身高度低于 0.18 m 或倾角超过 0.8 rad。

| --- | ---: | ---: | ---: |
| 站立偏航 | 0 rad/s | -0.142 rad/s | 0.315 m |
| 前进 | +0.6 m/s | +0.570 m/s | 0.294 m |
| 后退 | -0.6 m/s | -0.375 m/s | 0.299 m |

55 个回合均未触发上述跌倒判据，且每回合都有 6 s 稳态数据。运动指令下机身高度平均 **0.299 m**，比站立时的 **0.315 m** 低约 1.6 cm，比训练高度目标 **0.34 m** 低约 4.1 cm。站立时 FL/FR 足端接触占空比均为 **1.0**，HL/HR 均为 **0.0**；HL/HR 小腿接触占空比却为 **0.998/1.000**。这表明站姿由前足与后小腿支撑，而非四足站立；同时存在约 -0.142 rad/s 的偏航漂移。运动时四足接触占空比分别为 FL 0.474、FR 0.526、HL 0.613、HR 0.642，四条小腿也有约 0.10～0.17 的接触占空比；步态时钟匹配 0.779，摆动相刮地率 0.262，支撑脚滑移速度 0.132 m/s。

同一名义物理条件下的零动作对照位于 `benchmark_zero_actions_5trials/`：55 回合均未触发跌倒，站立时 FL/FR 足端接触占空比均为 1.0，HL/HR 均为 0.0；四条小腿的接触占空比却均为 1.0。平均机身高度约 0.263 m，倾角约 0.197 rad，偏航速度接近零。策略使机身更高、更平，却引入站立偏航漂移；小腿承重在零动作下也出现，不能只归因于策略输出。轨迹 `benchmark_zero_actions_pose_trace/trace.log` 显示四足在 0.1 s 均有接触力，到约 0.6 s 后足接触力归零、两条后小腿各承受约 50 N；策略轨迹 `benchmark_stand_pose_trace/trace.log` 也出现同样的后小腿承重。四只足端碰撞球在组合后的 USD 中均存在、半径均为 22 mm 且已启用；传感器与刚体顺序已按名称核对。轨迹中的 `foot_z` 是足端刚体坐标原点高度，不等同于碰撞球最低点。

v2 的历史评测显示运动高度约 0.260 m、刮地率约 0.224、支撑脚滑移约 0.118 m/s。v3 的高度改善约 3.9 cm，但刮地和滑移指标没有同步改善。v2 与 v3 的 CSV 字段版本不同，这些重叠指标只用于判断趋势。

### v3.1：非足端接触惩罚单变量候选

零动作对照中，单独把初始高度调到足底近乎贴地、恢复 v2 的关节角、改用更伸展的对称关节角、将位置刚度从 30 提到 60、将求解器速度迭代从 0 提到 1，或将位置迭代从 4 提到 16，均未恢复后足接触。各结果分别保存在 v3 run 的 `benchmark_zero_actions_*` 目录。它们说明这些单项改动不能直接解决当前的后小腿支撑状态，尚不能排除其他姿态或物理参数组合。

当前 v3.1 只把 `undesired_contacts.weight` 从 `-1.0` 调到 `-3.0`；该项通过所有非足端刚体的接触力计数，运行时已确认包含四条小腿。v3 站立时后小腿持续接触，因此新权重在相同接触状态下会增加约 4 的未乘步长瞬时惩罚。电机、默认角、观测、动作、其他奖励和 PPO 参数保持 v3。这个改动只是训练假设，新策略是否愿意改成四足支撑需用新的 checkpoint 验证；旧 v3 checkpoint 的回放不会因奖励权重变化而改变。

已在 `/tmp/lite3_v3_1_smoke/` 用 64 个环境、1 次迭代完成启动检查并生成 `model_0.pt`。运行时奖励表确认权重为 `-3.0`；与 v3 的 `params/env.yaml` 对比，除测试所需的环境数 2048→64 外，只有该奖励权重变化。PPO 参数快照除迭代数 5000→1 和 run 名外一致。该短跑只验证配置可运行，不作为效果数据。

用户决定先小步续训。已用 64 个环境、1 次迭代验证从 v3 `model_4999.pt` 恢复策略、重置优化器和启用完整命令范围的流程；测试输出保存在 `/tmp/lite3_v3_1_resume_smoke/`，没有写入项目训练日志。RSL-RL 将 `--max_iterations` 解释为追加迭代数。正式实验先追加 300 次并用新 run 保存，评测后再决定是否继续。

### v3.1 续训 300 次的评测结论

正式 run 为 `2026-10-09_18-48-24_lite3_flat_shank_penalty_v3_1_ft300/`。从 v3 `model_4999.pt` 继续训练 300 次，已保存 `model_5000.pt`、`model_5100.pt`、`model_5200.pt` 和最终的 `model_5298.pt`。分别按 v3 同一协议评测：seed 42、5 trials × 11 种固定命令、8 s、2 s warmup、关闭域随机化与观测噪声。配置快照与 v3 的差异为非足端接触奖励 `-1→-3`，以及新环境从完整速度命令范围开始；机器人资产、观测和动作一致。

| 指标 | v3 `model_4999` | v3.1 `model_5298` |
| --- | ---: | ---: |
| 55 回合跌倒数 | 0 | 0 |
| 站立偏航速度 | -0.142 rad/s | -0.008 rad/s |
| 站立 HL/HR 足端接触占空比 | 0.000 / 0.000 | 0.497 / 0.000 |
| 站立 HL/HR 小腿接触占空比 | 0.998 / 1.000 | 0.476 / 1.000 |
| 站立 FL/FR 足端接触占空比 | 1.000 / 1.000 | 0.613 / 0.251 |
| 运动机身平均高度 | 0.299 m | 0.294 m |
| 运动四小腿平均接触占空比 | 0.129 | 0.145 |
| 运动摆动相刮地率 | 0.262 | 0.254 |
| 运动支撑脚滑移速度 | 0.132 m/s | 0.137 m/s |

后退实际速度从 -0.375 提高到 -0.431 m/s，左横移从 +0.251 提高到 +0.298 m/s；前进从 +0.570 变为 +0.554 m/s，右横移从 -0.285 变为 -0.258 m/s。站立偏航改善明显，但四足支撑目标未达成：右后足在 5 次站立回合中均为 0 接触，右后小腿始终接触，且部分前足也转为小腿支撑。运动高度下降约 5 mm。中间 checkpoint 的站立足端接触变化不稳定：`model_5100` 的右后足占空比约 0.40，但左后足仍为 0；`model_5200` 两只后足均为 0。没有一个 checkpoint 形成稳定四足站立，因此当前结果不支持继续沿此奖励单项长训。

运行时追踪核实 `undesired_contacts` 选中了小腿，1 条小腿接触时奖励项为 `-3`，2 条时为 `-6`（乘控制步长前）。这排除了奖励项未生效的解释。训练日志中该项的回合均值很小，不能据此否定回放中已测得的奖励函数输出。下一步应检查足端与小腿的几何/关节关系和站立目标，使默认站姿能够稳定由四足承重，再考虑新的训练改动。

## 2026-10-10：模型、域随机化与部署接口核对

- USD 四条小腿改为使用原有 `shank.STL` 网格凸包作为动态刚体碰撞体，并关闭原有 8 个胶囊碰撞。修正模型核对：URDF 中 `shank.STL` 只用于视觉，小腿碰撞是两段半径 15 mm 的圆柱；MJCF 使用 `shank.STL` 网格碰撞，当前 USD 是按 MJCF 配的，因此 USD/URDF/MJCF 三者碰撞并未统一。文件网格一致不等于碰撞表示一致。
- 机身质量随机化从偏置的 `(-0.33, 2.33) kg` 改为标称机身质量两侧约 `±0.56 kg`。此前 v3/v3.1 checkpoint 并非在新质量分布下训练，后续评测需先固定名义质量。
- 部署 ONNX runner 现在读取模型输入维度，支持旧 45 维和当前 47 维策略；47 维时按训练定义提供 0.6 秒周期的 sin/cos 步态相位。上一动作初始化为零，OnEnter 在工作线程启动前执行。控制频率对齐至 50 Hz；默认关节角、`kd` 和速度命令上限与当前训练配置对齐。
- 从 v3.1 `model_5298.pt` 导出了 `exported/model_5298.onnx`。C++ smoke test 对仓库旧 45 维 ONNX 和新 47 维 ONNX 均连续运行 40 次，12 维动作均为有限值；CTest 默认策略通过。

以上是代码和接口验证，不代表策略在新网格碰撞体或新质量分布下已经改善。重新训练前，先用新模型跑标准站姿与固定命令基准，再决定是否进入短程续训。

## 2026-10-10：Lite3 名义站姿与训练起步配置

- 部署 runner 中能作为训练侧基准的量已逐项核对：50 Hz；默认角 `HipX=0, HipY=-0.67, Knee=1.34`；动作比例 `0.125/0.25/0.25`；关节 PD `kp=30, kd=0.5`；速度命令上限 `1/1/1`。训练使用同一组值。runner 本身没有显式力矩和关节速度裁剪，因此训练资产继续采用 Lite3 URDF 声明的电机限制；MJCF 统一 `±30 N·m` 与 URDF `24/36 N·m` 的差异仍需独立确认，不能从 runner 推断出硬件限值。
- 名义零动作轨迹显示初始足端刚体原点高度约 `0.0285 m`，22 mm 球体底面距地约 `6.5 mm`。PD 只追踪默认关节角，没有重力前馈；机器人落地后关节在重力下偏离目标，机身高度下降并逐渐把载荷转到小腿。使用默认姿态时约 `0.6 s` 后两条后腿足端不再接触，后小腿接触力约 `50 N`。
- 几何给出了接触转移的原因：把 MJCF 的网格和关节变换按默认姿态前向计算，根高 `0.35 m` 时小腿碰撞网格最低点为 `z=0.006037 m`；足端球心为 `z=0.028539 m`，半径 `0.022 m`，球底为 `z=0.006539 m`。也就是说，小腿网格比足底低 `0.50 mm`，而足底自身离地仅 `6.54 mm`。下落时小腿先于足端碰地，之后容易分担载荷。相比之下，URDF 的两段圆柱最低处约在足端刚体原点上方 6 mm，距足底约 28 mm，不会产生相同的接触面。
- 部署 `StandUpState` 也有高度定义问题：`stand_height_=0.33 m` 被直接当作髋到足端球心的 IK 长度，计算得到 `HipY=-0.65354, Knee=1.27109`。用 MJCF 前向运动学验证，根高设为 0.33 m 时球心 `z≈-0.00010 m`，22 mm 球底 `z≈-0.02210 m`，即球体穿过地面约 22 mm。该 IK 把足端球心当成地面接触点，没有扣除球半径；碰撞求解只能靠压缩姿态和其他刚体接触消解穿透。
- 只修正高度语义还不够：将 IK 长度改算为 `0.33-0.022=0.308 m` 后，MuJoCo 前向运动学的足底接近地面，但小腿网格最低点仍比足底低约 `0.50 mm`；按 runner PD 跑 1 秒，后小腿仍各承受约 `44 N`。所以 stand-up 高度应修正，但四足失去独立支撑的首要几何问题仍是网格小腿碰撞下探到足底平面。
- 对照把初始姿态改为接近落地后测得的 `HipY=-0.53, Knee=1.49`，根高提高到 `0.41 m`，2 秒后仍约 `0.263 m`，后小腿接触占空比约 `0.92/0.93`。因此不把未经验证的新姿态写入训练默认值；先使用部署目标角和窄随机化，训练/评测时单独记录四足与小腿载荷。
- 平地首阶段域随机化已收窄：重置 roll/pitch ±0.05 rad、机身质量 ±0.1 kg、其他刚体质量倍率 0.98–1.02、质心 ±5 mm、地面摩擦 0.95–1.0、PD 倍率 0.95–1.05，小外力和推扰。训练稳定后再分组扩大。
- 新增仅用于 Lite3 的跌倒终止：根高低于 `0.18 m` 或倾角超过 `0.8 rad`；小腿接触继续走 `undesired_contacts=-3` 惩罚，不触发 `illegal_contact` 终止。新配置短基准通过，Termination Manager 已加载这两个条件，接触惩罚只选择四条小腿。
